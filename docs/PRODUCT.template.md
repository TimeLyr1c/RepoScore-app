# Product

Copy or rename this file to `PRODUCT.md`. Replace guidance with short answers; use `Unknown` for unresolved questions. Keep the MVP narrow and testable.

## Product name
Write the working name; it can change later.

## One-sentence description
Explain who it helps, what it does, and the useful outcome.

## Problem
Describe the concrete frustration or unmet need, and how people handle it today.

## Target users
Name the initial audience and their relevant situation. One clear audience is enough.

## Core use case
Describe the main journey from trigger/input to useful result.

## Goals
List the outcomes this project should achieve, in priority order.

## Non-goals
State what this version intentionally will not do to keep scope clear.

## MVP
List the smallest set of capabilities needed to complete the core use case. Include observable acceptance criteria.

## Future ideas
Capture possibilities without treating them as commitments or current scope.

## Platforms
Name intended platforms and any required versions, devices, browsers, or runtimes. Mark undecided targets.

## Constraints
Record real limits such as time, budget, offline operation, distribution, accessibility, or data handling. Avoid invented constraints.

## UX principles
Write a few practical rules that guide interaction choices, such as clear error recovery or minimal setup.

## Success criteria
Define how you will know the MVP is useful. Prefer observable outcomes over vague quality claims.

## Open questions
List unanswered product questions, what evidence would resolve them, and which block the next step.
