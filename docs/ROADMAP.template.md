Completion: observed reliability issues and measured performance needs are addressed.

## M4 — Product Expansion
Completion: a chosen post-MVP improvement delivers a verified benefit.
- [ ] Select one expansion based on evidence or user feedback.
- [ ] Define, implement, and verify its acceptance criteria.

## M5 — Release
Completion: the intended release is validated and ready for the chosen distribution path.
- [ ] Confirm release scope, known limitations, and version information.
- [ ] Run relevant build/tests and manual acceptance checks.
- [ ] Prepare release notes and identify release blockers.

Release can occur before expansion. Move M5 earlier or repeat release milestones as needed. Publishing remains a separate, explicitly authorized action.
