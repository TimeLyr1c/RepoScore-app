# 在版本 2 索引中保存文件夹层级

## Status
Accepted — 2026-10-12

## Context

MVP 需要文件夹及子文件夹、重命名、移动乐谱。M1 的版本 1 索引没有层级，已有 PDF 副本不能在升级时丢失。

## Decision

索引版本升级为 2：folders 保存 ID、名称和 parentID；Score 增加可为空的 folderID，空值代表根目录。逻辑文件夹与 PDF 的物理存储分开，重命名/移动仅原子修改索引，不搬动 UUID 命名的 PDF。

读取版本 1 时先验证记录，再将原始索引字节保存为唯一命名的 `index-v1-backup-<UUID>.json`，之后原子写入版本 2。只有迁移成功才发布加载状态；未来版本、损坏的记录、断开的层级或循环引用均保留原文件并报错。

## Reasons

保留既有 PDF 路径与 ID，降低迁移风险；文件夹层级规模较小，现有 JSON 索引足够。父子关系不依赖名称路径，父文件夹重命名不会使子文件夹或乐谱失联。

## Consequences

- 同一层级的文件夹名忽略大小写比较并进行 Unicode 规范化，不允许同名；不同层级可同名。
- 名称去除首尾空白，不接受空名称、`.`、`..` 或 `/`；导入的乐谱允许同名并保持独立副本。
- 文件夹按创建顺序、乐谱按导入顺序显示。当前目录导入直接设置归属。
- 本阶段不提供文件夹/乐谱删除、移动文件夹、标签或排序 UI。
- 每次写入成功才更新内存快照；失败保留原归属和副本。
- 备份仅保护此次索引迁移，不是完整曲库备份。回退到旧应用前需要恢复备份索引；旧版本不能直接读取 version 2。恢复会丢失迁移后新增的组织信息，不提供自动降级。

## Alternatives considered

物理目录移动：会改变现有阅读路径并增加文件与索引一致性工作，当前没有收益。数据库：现有小索引仍满足层级与验证需要。
