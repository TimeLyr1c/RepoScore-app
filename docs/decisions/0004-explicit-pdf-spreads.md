# 显式计算阅读页组

## Status
Accepted — 2026-10-12

## Context

MVP 需要单双页、可选封面单独展示及末尾单页。切换模式或横竖屏时不能回到第一页；点击和滑动应遵守同一套配对规则。

## Decision

用 PageLayout 从物理页码计算当前可见的一页或两页。PDFKit 继续渲染页面；容器按页组水平排列一个或两个单页 PDFView，封面及末尾单页占用完整容器。页面锚点由 SwiftUI 保存，模式或封面设置改变时保持同一物理页可见；旋转只重新适配显示尺寸。

页组左右外侧各 25% 的单击、横向滑动及上一页/下一页按钮使用同一分页规则。中心点击不翻页；双击优先留给 PDFKit，放大后边缘点击/滑动不翻页，保留平移和缩放操作，可用按钮翻页。

## Reasons

显式页组可以直接测试封面偏移、单双页切换和奇偶数边界，并保证单独页面居中使用完整阅读区。系统 [displaysAsBook](https://developer.apple.com/documentation/pdfkit/pdfview/displaysasbook) 提供封面选项，但本轮选择由应用统一控制配对、单页占位及交互，而不是依赖视图内部当前页去反推用户阅读位置。

## Consequences

- 双页模式在横竖屏下均保持双页，竖屏的每页会较小，用户可手动改为单页。
- 单双页及封面设置只保留在当前打开的阅读会话，未持久化阅读进度或每份乐谱的设置。
- 切换页组会重建最多两个 PDFView，缩放恢复适配；旋转也恢复适配，不承诺保留放大后的局部坐标。
- 无额外 PDF SDK，不修改原 PDF 内容；真实 iPad 的大文档性能、缩放及手势体验仍需验收。

## Alternatives considered

直接使用 PDFKit twoUp：可减少容器代码，但边界单页尺寸和位置由系统布局决定。栅格化全部页面：增加内存及清晰度管理工作，不符合最小实现。
