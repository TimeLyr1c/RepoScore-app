# RepoScore — Product

## 产品定位

RepoScore 是主要面向 iPad 的轻量乐谱 PDF 阅读与管理工具，帮助音乐人在个人练习和团队排练时收纳、找到并阅读已有乐谱。RepoScore 为暂定名称。

## 要解决的问题

希望用较少的操作收纳和找到乐谱，并在阅读时保持界面简洁、减少干扰。现有工具的复杂度和分类体验未能满足这一需求；本产品优先解决自己的阅读与管理流程，不以复制竞品全部功能为目标。

## 目标用户与目标

面向使用 PDF 乐谱的音乐人。目标按优先级排列：

1. 导入后可靠保存乐谱，随时离线打开。
2. 通过熟悉的文件夹组织方式收纳和找到乐谱。
3. 在横竖屏下舒适阅读，用点击或滑动翻页。

演出也是长期使用场景；专用演出功能放入后续更新计划，不作为首版验收条件。

## 核心使用路径

从系统文件选择器导入 PDF → 应用保存独立副本到曲库 → 用文件夹收纳 → 从曲库再次找到并打开 → 选择阅读方式并翻页。

系统文件选择器是本轮 bootstrap 采用的首个导入入口；分享菜单、批量导入等入口留待以后决定。

## MVP

### 导入与本地曲库

- 导入 PDF，在应用内保存独立副本；不依赖外部原文件继续存在。
- 导入后的乐谱在应用重启后仍可打开，阅读不需要网络或登录。
- 曲库展示已导入的乐谱，点击后直接打开；不提供独立的预览流程。
- 无法读取或无效的 PDF 应明确提示导入失败，不留下看似成功的曲库项目。

### 文件夹组织

- 第一版使用文件夹，遵循普通文件系统的组织方式：根目录、文件夹及子文件夹；每份乐谱位于一个文件夹或根目录。
- 最小管理能力包括创建及重命名文件夹、移动乐谱到文件夹、按层级浏览并打开乐谱。
- 根目录用于存放尚未归入文件夹的乐谱，不另设强制分类。
- 标签、乐器、专辑等更细分类不属于 MVP。
- 文件夹名称去除首尾空白；同一层级忽略大小写比较，不允许同名，不同层级可以同名。名称不能为空、`.`、`..` 或包含 `/`。
- 文件夹和乐谱可通过行上的菜单操作；乐谱可移动到根目录或任意已有文件夹。本阶段不提供删除或移动文件夹。

### 阅读

- 支持单页与双页视图，以及横屏和竖屏阅读。
- 支持点击和滑动翻页。
- 双页视图允许用户选择：第一页单独展示，之后两页配对；或从第一页开始两页配对。
- 配对后如末尾只剩一页，最后一页单独展示。
- 切换阅读模式或旋转屏幕时应保持当前阅读位置，不意外回到第一页。
- 点击阅读区左侧或右侧外缘各 25% 区域，分别向前或向后翻页；中间点击不翻页。左滑向后、右滑向前，单双页遵循相同页组规则。
- 缩放时以平移阅读为主，放大后边缘点击/滑动不翻页，仍可用按钮翻页。阅读中用导航栏返回按钮退出，避免横向滑动误返回曲库。
- 旋转或切换页组时恢复页面适配尺寸，不承诺保留局部缩放位置。单双页及封面选项保留在当前阅读会话，跨次打开的阅读设置/进度暂不持久化。

## 非目标（MVP）

- 在线乐谱搜索、下载或 IMSLP 集成。
- 云端共享、账户登录和多设备同步。
- OCR、PDF 内容编辑，以及新增或编辑标注。
- 蓝牙踏板翻页和专用演出模式。
- 独立的 PDF 预览流程。

## 平台与约束

- 面向 iPadOS；最低系统版本由 bootstrap 记录在架构文档中，属于可调整的技术选择。
- 导入后的 PDF 和曲库资料由应用本地保存；外部原文件移动、删除或不再可访问，不影响已导入副本。
- 导入来源可能需要网络；离线保证从导入成功后开始。
- MVP 不依赖后端服务。分发渠道、收费方式和最终名称暂未确定，不阻塞 bootstrap。

## UX 原则

快速、简约、少干扰。组织方式尽量符合文件夹使用习惯；打开乐谱直接进入阅读，错误要有明确提示。

## MVP 成功标准

- 成功导入 PDF 后，重启应用、断网且外部原文件删除，仍能从曲库打开该乐谱。
- 可以建立文件夹及子文件夹、重命名文件夹、移动乐谱，并按层级再次找到乐谱。
- 单页、双页及横竖屏下均能阅读；点击和滑动能正确翻页且不越过文档边界。
- 双页两种起始方式均正确；剩余单页能展示；旋转或切换模式后阅读位置不丢失。
- 无效或无法读取的 PDF 不会产生不可用的成功导入记录。

这些标准用于完整 MVP 验收，不代表 bootstrap 已实现这些功能。阅读与触摸体验需在真实 iPad 上验证。

## 后续更新方向

- 专用演出流程，以及踏板翻页。
- 标注、搜索、排序、收藏和阅读进度等功能按实际使用需要再评估。
